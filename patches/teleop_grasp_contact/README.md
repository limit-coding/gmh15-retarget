# 补丁草案：抓取时不因跟踪误差而失能（未部署）

对象：`yubi-pi:~/gmh15-sdk/teleop/teleop_control.py`（本项目自己写的 teleop 服务器，不是厂家代码）。
状态：**只是草案，没有拷到 Pi，也没有重启容器。** 本地测试通过，没有在真手上验证过。

## 问题
`tick()` 里只要发出的目标和实测角度相差超过 `MAX_TRACKING_ERROR_DEG = 10°`，就会 `stop()`，也就是 `disableMotor`。
手指捏住物体后被挡住，目标继续以 8°/s 往里收，大约 1.25 s 后偏差超过 10°，电机失能，物体就掉了。

## 改法（`teleop_control.diff`）
- arm 时记录五根手指的触觉力，作为基线 `force_baseline`。这样拇指空载就有约 0.7 N 的读数不会被误判为接触。
- 每个控制周期，在原来的缓动步长算完之后、偏差检查之前，调用 `apply_grasp_cap()`：
  - 某根手指的力超过基线 `CONTACT_DELTA_N = 0.5 N`，就算这根手指在接触。这根手指对应的关节（四指 MCP；拇指的 CMC/MCP/IP 三个都算）的**收紧方向**目标，最多只能比实测角超前 `GRASP_LEAD_DEG = 6°`。位置环下，这个超前量就决定了握力的上限；
  - 力超过 `MAX_CONTACT_FORCE_N = 15 N`：这根手指不再继续收紧；
  - 张开方向从不限制。
- 原来的 10° 偏差检查**原样保留**。接触的手指因为目标被限住，偏差不会超过 6°，所以不会触发；没有接触信号时，行为和原来完全一样。
- `status()` 里多返回 `grasp_contact`（哪些关节在接触、超出基线多少 N）以及上面几个阈值。

故障码、电机使能丢失、反馈失效、心跳超时、SDK 拒收目标，这些路径一个都没改，触发后照样失能。

## 已知局限（上真机前要清楚）
- 触觉只在指尖垫上。物体如果顶在指节或者手掌上，不会产生接触信号，仍然会在 10° 时失能。下一步可以加电机电流作为第二个接触信号（SDK 有 `getMotorActualCurrent`，但现在采集循环里没读）。
- 触觉和控制都是 10 Hz，接触被识别大约有 100 ms 延迟。按 8°/s 算，这段时间多超前 0.8°，没问题；**以后如果把缓动加快**（比如 60°/s），超前量可能在接触被识别之前就超过 10°，到时要重新校核。
- 0.5 N、6°、15 N 都是估计值。6° 超前在真手上对应多大握力，需要实测（读触觉力）。
- 如果 arm 时手里已经拿着东西，基线会把这部分力算进去，接触就识别不出来，结果退回到原规则，也就是还会失能。

## 部署步骤（需要你确认后再做）
`teleop/` 目录是以只读方式挂进容器的（见 `start_teleop_right_*.sh`），所以部署就是换文件再重启：
1. 在 Pi 上备份：`cp -a ~/gmh15-sdk/teleop ~/gmh15-sdk/teleop-backup-$(date +%Y%m%d-%H%M)`；
2. 把 `teleop_control.py` 和 `test_teleop_control.py` 拷到 `~/gmh15-sdk/teleop/`，先在容器里跑测试；
3. `sudo docker stop gmh15-teleop && sudo docker rm gmh15-teleop`，再用原来的启动脚本重新启动；
4. 真机测试按这个顺序：空手开合（行为应和原来一致）→ 捏一块软海绵（应当保持使能，看 `grasp_contact` 和触觉力）→ 捏一个硬物体 → 物体顶在指节上（预期：仍然失能，确认上面那条局限）。
