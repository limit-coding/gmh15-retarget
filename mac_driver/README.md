# Mac 本机控制 GMH15

## 官方例程网页（2026-11-07）

双击项目根目录 `官方例程控制台.command`，打开 <http://127.0.0.1:8767/>。

- 已接入：官方位置往返、官方 USB 连接检查、直接调用 SDK 的 10 Hz / 30 Hz 连续小幅开合。
- 点击「开始运行」后其他启动按钮锁定；点击「停止当前例程」（或 Esc）后，等待「电机失能已确认」再运行下一个。例程自然结束也会失能，关闭网页会请求停止。
- 每个例程有有限运行时长；控制台另有 45 秒超时停止。页面只监听本机，不自动接管正在运行的遥控服务；使用前关闭旧版手势程序与灵巧手服务。
- 运行日志显示在网页，完整原始日志保存在 `runs/example_web/`；底层 SDK 记录保存在 `runs/performance-20261107/web-*.jsonl`。
- 网页服务入口：`.venv/bin/python scripts/run_examples_web.py --open`，Ctrl+C 关闭并清理当前例程。

例程入口复用 `tools/run_sdk_performance.py`。停止时只向 SDK 子进程发送一次终止信号，保留 USB 转发到失能/配置恢复完成；清理期间忽略重复停止信号。新增测试覆盖单实例、停止后解锁、来源验证，以及不终止 USB 转发进程。官方完整握拳、力控和相机例程未放入此页。

## 频率优化与官方例程对照（2026-11-07）

新增入口：双击项目根目录 `流畅手势控制灵巧手.command`。它使用 30 Hz 控制与反馈，仍在网页上手动使能；原 `手势控制灵巧手.command` 保留默认 10 Hz。切换前关闭旧版服务；流畅版发现正在运行的服务频率不匹配时会明确提示。客户端也会服从服务器公布的频率上限。

右手 H15R49G00039，Mac USB + OrbStack + SDK 3.9.0，小幅正弦往返（四指 0–2000，拇指 0–800/1200/1200，周期 4 秒）：

| USB 实际发出的指令 | 备份原版（20 秒） | 优化版（40 秒） |
|---|---:|---:|
| 平均频率 | 6.30 Hz | 27.82 Hz |
| 更新间隔中位数 | 113 ms | 35 ms |
| 更新间隔 95 分位 | 336 ms | 57 ms |
| 最长更新间隔 | 427 ms | 295 ms |
| 电流绝对值峰值（SDK 单位） | 356 | 356 |

两轮均无控制保护报错，结束后确认失能。仍存在偶发长间隔，尚不能承诺完全无卡顿；这些是小幅空手轨迹的测量，不包含真人相机到机械手的完整延迟、满行程或带负载测试。此前记录的相机约 15 fps 也可能继续限制真人跟手效果。

改动：HTTP 通信时间计入发送周期；控制器按固定时间表发送，容忍小幅采集抖动；纯电机模式支持显式选择 5–30 Hz（默认 10 Hz）；运动期间不再轮询速度/电流配置，显示本会话应用值，继续逐帧读取实际位置和电流、检查故障。电机速度、行程、限速、握力上限、心跳、急停、保持/松开逻辑保留。57 项测试通过，包括新增定时抖动和 30 Hz 下的限速/过流保护检查。

官方对照：`open_usb_device.py` 原文件在连接复用与失能清理的监督下运行成功；`position_control_demo.py` 使用其原位置模式准备函数及原目标/等待时间，连接换成 USB，增加故障清除和 450 电流上限，正常往返到位。直接用官方 SDK 连续发送同样正弦目标，10/30 Hz 分别实测 10.00/29.98 Hz（各 8 秒）。最初增加 50 Hz 反馈采样的官方位置测试曾出现读取超时及异常反馈，已停止并失能；保留失败记录。因此不把“例程跑通”等同于硬件完全没有偶发卡顿。

记录：`runs/performance-20261107/`，最终对照为 `comparison-original*` / `comparison-optimized*`，USB 间隔统计为 `*.usb-summary.json`。备份：`backups/before-frequency-20261107.tar.gz`，已解压原件在同名目录；原 retarget 求解、映射、滤波与标定文件未修改。`tools/compare_control_rates.py` 是实机运动测试，`tools/run_sdk_performance.py --allow-motion` 是官方 SDK 对照，运行前须关闭服务并让手空载。

## 当前默认：纯电机界面

`启动灵巧手.command` 现已切换到 **7 路电机专用界面**，不启动摄像头、触觉采集或 MuJoCo 渲染。运行命令为：

```sh
.venv/bin/python scripts/run_mac_hand.py --motor-only --no-render --allow-motion
```

访问 <http://127.0.0.1:8765/>：先初始化，再启用；每一路可调整目标角度，点击发送才运动。显示实际角度和7路电机原始位置；反馈过期时阻止控制，采集进程退出时明确显示离线。服务端同时限制四指 0–45°、拇指各 0–30°、PIP 固定 0°。这些是当前测试范围，并非机械极限。

**当前实测限制（2026-11-07 更新）**：
- 位置初始化已修复。原因：电机 1（食指）的回零状态寄存器 0x2120 锁存为 1，`getFaultCode` 读不出；SDK 要求 7 路都为 2，否则等 5 秒返回 0。现在初始化前先调用厂家 `clearFaultCode`，实测经服务端 1.9 秒返回 1。抓包见 `../runs/mac_driver/usb_trace_*.txt`，诊断入口 `scripts/run_mac_hand.py --init-diag`，抓包开关 `GMH15_USB_TRACE=文件路径`。
- 当天先发现电机 3 无名指卡住（使能后电流 600–1000，位置不变），电机 6 拇指 MCP 不执行（电流不上升）。用户现场处理后复测，**7 路全部通过**：+10° 往返，实测 8.7–10.4°，回位误差 <1°，使能期间电流峰值都不超过 182。日志：`../runs/mac_driver/motor_check-after-user-fix.log`。

旧版混合采集曾在触觉读取异常后退出或原生库崩溃，新的默认入口完全跳过相关采集接口。以下相机、触觉和模型验证属于之前的迁移记录；它们现在不在默认界面中运行。

迁移日期：2026-11-07。控制 USB、掌内相机直接接 Mac，运行时不再使用树莓派或 SSH 隧道。

## 手势控制真机（2026-11-07 起）

- 一键启动：在 iTerm2 运行 `~/灵巧手/scripts/start_all.sh`（或双击 `手势控制灵巧手.command`，会自动用 iTerm2 打开）。依次启动 OrbStack、灵巧手服务（已在运行就复用）、需要时做位置初始化、手势程序（Mac 摄像头 = OpenCV 编号 1），并打开 <http://127.0.0.1:8766/>；在网页上点「使能真机」。Ctrl+C 退出，脚本启动的服务会一起停止。
- 同一时间只开一个控制页面：`/motors` 电机页的停止按钮/空格会停掉手势控制。
- 仿真按实测：手指路径 `measured`（s = 电机计数/10000），拇指范围 CMC 0–109°、MCP 0–63°、IP 0–84°。
- 发送给真机的是电机计数（`hw_map.counts_from_sim`），四指用满 0–10000，拇指 MCP/IP 上限 7200/7700。旧的关节角路径（MCP 0–45°、拇指 0–30°）用 `--joint-mode`。
- 服务端保护：任一电机电流连续 2 帧 > 600 → 失能；电机目标与实际相差 > 2500 计数 → 失能；心跳 0.6 秒。速度：电机计数 8000/s 软件限速，实测电机物理速度约 4500/s（全握约 2.2 秒）。环境变量 `GMH15_MOTOR_SLEW_CPS`、`GMH15_MOTOR_SPEED`、`GMH15_CURRENT_STOP` 可调。

## 抓握与保持（2026-11-07）

- 使能期间电机电流上限设为 450（`GMH15_GRIP_CURRENT`，停止后恢复 1000），握力因此有上限；空手运动电流峰值约 270，不受影响。
- 接触处理：电机目标最多比实际位置超前 1500 计数（`GMH15_CONTACT_LEAD`）。手指被物体挡住时会以受限的力继续夹紧，不再因“目标与实际相差过大”而失能。
- 网页「✊ 保持握持」：由服务端冻结当前握姿，此后不需要遥操作和心跳，可以关掉手势程序（退出时不会再发停止）。「✋ 松开」：手慢慢张开到 0，然后自动失能。最长保持 30 分钟（`GMH15_HOLD_MAX_S`），超时自动松开。「■ 停止」任何时候都是急停（立即失能，物体会掉）。
- 真机空手验证：保持期间停掉心跳 6 秒，位置偏差 ≤1 计数；松开约 1.1 秒完成并失能，电流上限恢复为 1000。实物抓取尚未验证。

## 电机原始行程实测（2026-11-07，`scripts/motor_range_probe.py`，数据 `runs/motor_range.jsonl`）

页面 <http://127.0.0.1:8765/motors> 可直接控制 7 路电机原始位置（0–10000），并显示电流、关节角和编码器。

| 电机 | 可用行程 | 关节随动（SDK 正解） | 电流峰值 |
|---|---|---|---|
| 1–4 四指 | 0–10000 全程 | 0–约 6900：只有 MCP 弯，0→80°（约 11.6°/1000 计数）；6900–10000：MCP 停在 80°，PIP 0→80°、DIP 0→75° 一起弯 | <200 |
| 5 拇指 CMC | 0–10000 全程 | 0→109° | 244 |
| 6 拇指 MCP | 约 0–7500（再往上电流超过 500，顶到极限） | 0→65° | 510 处停 |
| 7 拇指 IP | 约 0–8000 | 0→89° | 712 处停 |

结论：四指是“先弯根部、再卷远端”（腱驱动，和 retarget 的 `mcp_first` 路径一致）。原来关节角接口限制在 MCP 0–45°、PIP=0，只用到四指约 37% 的电机行程，所以真机看起来握不紧。拇指 MCP/IP 的极限是在其他关节都为 0 时测的。

## 使用

在项目目录双击 `启动灵巧手.command`，然后打开 <http://127.0.0.1:8765/>。

启动会开放网页控制操作，但不自动初始化或使能。需要运动时，先在网页执行位置初始化，再启用控制。保留原服务的8°/秒缓动、10 Hz 控制、0.6 秒心跳超时、初始化和故障检查；纯电机入口将角度限位收紧到上述测试范围。初始化可能造成运动。

双击 `停止灵巧手.command` 或在启动终端按 Ctrl+C 停止服务。正常停止先通知串口采集进程执行原控制器的失能与清理。USB 被拔掉后无法再通过断开的线发送失能命令；实物断连行为仍需现场验证。

只读检查（先停止正在运行的服务，避免同时占用串口）：

```sh
.venv/bin/python scripts/run_mac_hand.py --probe
```

只读网页（所有电机写接口由白名单锁定）：

```sh
.venv/bin/python scripts/run_mac_hand.py --camera 1
```

允许网页手动控制：

```sh
.venv/bin/python scripts/run_mac_hand.py --camera 1 --allow-motion
```

启动前需打开 OrbStack。双击启动和检查脚本会自动打开它，入口会等待环境就绪。

现有 `hand_client.py`、`GMH15HttpDriver` 和 `scripts/run_sim.py` 继续访问本机 8765 端口即可。不要同时开启原先的 8765 SSH 隧道。`run_sim.py` 按 `a` 前，仍需先在网页初始化，并使用其原有硬件开关。

## 复用之前的手部动作 retarget

先启动本地驱动，再双击项目根目录的 `手势控制灵巧手.command`。它打开原来的 `scripts/run_sim.py` 优化版 retarget，使用 Mac FaceTime 相机（OpenCV 编号 1；编号和 ffmpeg 列表顺序不同，0 是掌内相机）和原有 `config/sim_calib_right.json` 标定；掌内相机 1 仍由驱动服务使用。

窗口初始不使能：先举右手检查追踪和模型，必要时张开按 `o`、握拳按 `f` 重新标定；需要实物跟随时先在网页位置初始化，再回到手势窗口按 `a`。按 `d` 失能、`q` 退出并失能。网页和手势程序不能同时占用控制权。

这一路沿用真机保守范围：四指 MCP 0–45°、四指 PIP 固定 0°、拇指三个关节各 0–30°。原 retarget 在完整模型范围内的捏合效果不能直接等同于当前真机范围内的效果；完整握拳、捏合及腱耦合曲线仍需实测后调整。

相机索引随系统设备变化时，用以下命令找到 `Usb HD` 对应编号，再调整 `--camera`（不要选择操作者相机）：

```sh
ffmpeg -hide_banner -f avfoundation -list_devices true -i ''
```

`--device /dev/cu.…` 可指定控制器；多只 STM32 接入时必须显式指定端口。当前入口一次运行一只手，左右手各自仍校验原设备序列号。未验证双手并发。

## 文件与迁移方式

- `pi_snapshot/`：从 Pi 现用 `~/gmh15-sdk/teleop/` 只读拷贝的源码，保留原件。
- `teleop_control.py`：沿用 Pi 控制逻辑，增加只读电流/速度配置查询白名单。
- `teleop_acquisition.py`：增加纯电机采集分支，跳过触觉和接触查询，读取电机电流及限速配置。
- `motor_only.html`：新的纯电机界面，无图像或模型资源。
- `teleop_buttons.js`：保留 Pi 旧版界面脚本，纯电机界面不加载它。
- `teleop_server.py` / `live_media.py`：增加串口参数、Mac 相机转发、自定义模型路径。
- `serial_bridge.py`：Mac 原生串口独占读取，将 USB CDC 字节流转给本机 Linux。仅监听回环地址，连接需随机令牌。
- `container_entry.py`：Linux PTY 转发、进程监督及正常退出清理。SDK 仍负责厂家协议和运动学。
- `camera_relay.py`：Mac AVFoundation 相机，带随机令牌的本地 JPEG 转发。
- `../scripts/run_mac_hand.py`：统一启动和停止监督；容器名 `gmh15-mac`，禁止同名并发启动，不自动重启或上电自启。
- 原厂家模型仍在 `../vendor/yubi-pi_gmh15-sdk/models/`。
- 运行证据在 `../runs/mac_driver/`。只读快照中的 `sdk_write_calls=0`、`initialization_count=0`、`command_count=0`。

Linux 镜像负责封闭的厂家库；Mac `.venv` 增加 `pyserial==3.5`，继续使用原有 OpenCV。Linux 侧通过 `host.docker.internal` 访问 Mac 的回环服务；已在本机 OrbStack 验证。Docker Desktop 等其他运行环境未验证。
